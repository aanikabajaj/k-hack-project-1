## 1. `/waitlist` could show a stale list after joining one from `/schedule`

**File:** [`src/app/schedule/page.tsx`](../src/app/schedule/page.tsx)

Booking a full class from `/schedule` lands it as `"waitlisted"` and invalidated
`bookings.mine` and `classes.list` - but not `bookings.waitlisted`, which is the query
`/waitlist` actually reads. `/waitlist`'s own cancel handler already invalidated all three;
`/schedule`'s book handler was missing the third one.

**Fixed:** added `await utils.bookings.waitlisted.invalidate();` to `book`'s `onSuccess`,
matching the pattern `/waitlist` already used.

## 2. `book`, `cancel`, and `reschedule` weren't atomic

**Files:** [`src/server/routers/booking-rules.ts`](../src/server/routers/booking-rules.ts),
[`src/server/routers/bookings/member.ts`](../src/server/routers/bookings/member.ts),
[`src/server/routers/reschedules.ts`](../src/server/routers/reschedules.ts)

Each mutation was a sequence of separate reads and writes, not one transaction: `book`
checked capacity then inserted in two round trips; `cancel` updated, refunded, and promoted
the next waitlisted member in three; `reschedule` did all of that plus an insert and a
second update. Two requests racing each other for a class's last open spot could both read
"not full" before either had written anything, and both land as `"booked"` past capacity.

**Fixed:** `booking-rules.ts`'s helpers (`activeMembershipFor`, `isClassFull`,
`refundIfEligible`, `promoteNextWaitlisted`) and `reschedules.ts`'s `checkReschedule` now
take a `DbOrTx` parameter type instead of `typeof Db`, so they work unchanged whether called
with `db` or the `tx` from inside a transaction. `book`, `cancel`, and `reschedule` each now
run their full body inside `ctx.db.transaction(async (tx) => ...)`. Read-only queries were
left as plain `db` calls.

`DbOrTx` itself is defined in `src/db/index.ts` in the combined project - this folder
doesn't carry its own copy of `db/`, same as it doesn't carry `server/trpc.ts` or
`_app.ts` (see this folder's README). These two files match
`flexfit-studio-combined-final`'s versions exactly; the fix is real, it's just only
runnable from the combined project.
